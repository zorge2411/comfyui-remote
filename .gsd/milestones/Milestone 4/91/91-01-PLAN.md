# Plan 91.1: PromptValidator in Main Code

## Objective

Turn the corpus-only validator into an app-side prompt validator that mirrors ComfyUI's `validate_prompt`/`validate_inputs` (D-01 to D-03). Keep the corpus tests working on top of it, unchanged.

<task type="auto">
  <name>domain/PromptValidator.kt</name>
  <files>app/src/main/java/com/example/comfyui_remote/domain/PromptValidator.kt (new)</files>
  <action>
    `PromptValidator.validate(prompt: JsonObject, objectInfo: JsonObject, checkFileValues: Boolean = true): List<Issue>`.
    - `Issue(nodeId, classType, nodeTitle (from _meta.title, else classType), kind, inputName?, message, severity)`.
    - `Kind`: MISSING_NODE_TYPE, NO_OUTPUT_NODE, BAD_LINK, TYPE_MISMATCH, REQUIRED_INPUT_MISSING, INVALID_VALUE_TYPE, OUT_OF_RANGE, VALUE_NOT_IN_LIST.
    - Severity follows D-03: ERROR for the structural kinds, WARNING for value kinds.
    Steps:
    1. Every `class_type` missing from objectInfo → MISSING_NODE_TYPE.
    2. Output nodes are those with `output_node: true`. If there are none, NO_OUTPUT_NODE. Otherwise walk links from them and validate only reachable nodes (server behaviour). Nodes with unknown types are reported once and not walked.
    3. For each reachable node, carry over the effective-spec logic from `ApiPromptValidator` (dynamic combos, autogrow `min: 0`, `COMFY_MATCHTYPE_V3`, `*`, comma lists, `widgetType`):
       - REQUIRED_INPUT_MISSING;
       - BAD_LINK: not a 2-element array, or the source is absent;
       - TYPE_MISMATCH;
       - INVALID_VALUE_TYPE, e.g. "abc" for INT;
       - OUT_OF_RANGE, using the spec's `min`/`max`;
       - VALUE_NOT_IN_LIST: legacy, V3 COMBO and dynamic keys. Skip empty option lists. File-looking values are checked only when `checkFileValues`.
    4. Messages use the server wording ("Required input is missing", "Return type mismatch between linked nodes", "Value {v} bigger than max of {max}", "Value not in list: …").
    Put the shared type/combo helpers in one place (`GraphToApiConverter.typesCompatible`/`comboOptions` or a small `SpecUtil` object); don't duplicate them.
  </action>
