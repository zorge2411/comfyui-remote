# Plan 99.3: Queue UI, Download All, Notifications, Device Check

## Objective

The user-facing part of the download queue:
- **Download all** on the Missing Models card;
- a **Model downloads** section on the Queue screen, with reorder, remove, cancel, retry and clear;
- **notifications** while minimized.

It ends with a device check against extension v2.

  <action>
    `ExecutionService`:
    - create the channel `model_downloads` ("Model downloads", IMPORTANCE_LOW) next to the existing channel;
    - collect `app.modelDownloadRepository.downloads` and keep a `batch` of jobs seen since the queue was last idle;
    - while `ModelDownloads.summary(list)` isn't null, post or update id 2: ongoing, `setOnlyAlertOnce`, a determinate `setProgress(100, percent, false)` (or indeterminate), and a content intent to MainActivity;
    - when it becomes null after being active:
      - cancel id 2;
      - post id 3 with `finishedSummary(batch)`, auto-cancel;
      - reset `batch`.
    - Skip everything when `NotificationManagerCompat.areNotificationsEnabled()` is false.

    `DynamicFormScreen`:
    - use a `rememberLauncherForActivityResult(RequestPermission())` for `POST_NOTIFICATIONS` (API 33+), following the `ImageSelector.kt` pattern;
    - request it once before the first Download or Download all when it isn't granted;
    - the download starts whatever the answer.
  </action>
