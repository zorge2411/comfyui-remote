# Plan 102.1: Connection State and Server Queue

## Objective

Build the data side of the new navigation (102-CONTEXT D-03, D-04, D-05):
- the server's queue, parsed and editable;
- auto-connect on start;
- one connection gate the screens can use.

<task type="auto">
  <name>ServerQueueRepository (app-scoped)</name>
  <files>
    app/src/main/java/com/example/comfyui_remote/data/ServerQueueRepository.kt (new)
    app/src/main/java/com/example/comfyui_remote/ComfyApplication.kt
    app/src/main/java/com/example/comfyui_remote/MainViewModel.kt
    app/src/main/java/com/example/comfyui_remote/QueueViewModel.kt
  </files>
  <action>
    - Follow `ModelDownloadRepository`: it's constructed in `ComfyApplication` and builds its API from the saved preferences.
    - State:
      - `jobs: StateFlow<List<ServerJob>>`;
      - `lastError: StateFlow<String?>`;
      - `rememberName(promptId, name)` (a bounded map of about 200 entries).
    - `refresh()` does a `getQueue`, parses it with the known names, and publishes. It is triggered:
      - on CONNECTED;
      - on websocket messages whose `type` is `status`, `execution_start`, `executing`, `execution_success`, `execution_error` or `execution_interrupted` (debounced 300 ms);
      - by `startPolling()`/`stopPolling()` (every 3 s), which the Queue screen calls while visible.
    - On DISCONNECTED the list is cleared.
    - Actions:
      - `cancel(job)`: `editQueue({"delete":[id]})`, then refresh;
      - `interrupt(job)`: `interrupt({"prompt_id": id})`, then refresh;
      - `clearPending()`: `editQueue({"clear": true})`.
      - Errors go to `lastError` with a short message.
    - `MainViewModel` (after it gets a `prompt_id` in execute and queue paths) and `QueueViewModel.processQueueItem` call `rememberName(promptId, workflow.name)`.
  </action>
  <verify>gradlew.bat assembleDebug</verify>
  <done>Builds.</done>
</task>
