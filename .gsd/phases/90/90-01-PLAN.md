# Plan 90.1: Frontend Link Resolution (Virtual Nodes, Bypass, Broken Widget Links)

## Objective

Make `resolveRealSource` follow the frontend's `ExecutableNodeDTO.resolveOutput`:
- recognise the virtual node types explicitly;
- pass the target type down the whole chain;
- port `_getBypassSlotIndex`, which removes the same-index fallback;
- fall back to the saved widget value when a widget input's link doesn't resolve.

This fixes `3d_hunyuan3d_multiview_to_model` (C3) and lays the groundwork for PrimitiveNode and Set/Get in 90.2.

       - `addLink` passes the link's own type, from `linkTypeMap`, as `targetType`. So does the fallthrough mapper.

    3. **`isValidConnection(a, b)`** as in RESEARCH §2: null, `""` or `*` matches anything; otherwise compare case-insensitively, split on `,`, and match on any common type.
    4. **Bypassed source.** Replace `bypassInputLink` with a port of `_getBypassSlotIndex(slot, targetType)`, steps 1–5 in RESEARCH §2. The output type comes from `outputs[slot].type`.
       - If the chosen input is unlinked, return null.
       - If the index is -1, log `CONVERT_DEBUG` and return null. There is **no** same-index fallback any more.

    5. **Virtual or phantom source.**
       - Reroute, SetNode, GetNode, or a PrimitiveNode reached indirectly: use the linked input at index `sourceSlot` (`getInputLink(slot)`). GetNode resolution comes in 90.2; for now GetNode drops. PrimitiveNode has no inputs, so it drops.

       - Store the phantoms' input slots with their types, not just link ids.
    6. **Delete** the stale comment block after the node loop (D-03).
    Avoid:
    - changing Mode A (keyed inputs) or subgraph expansion;
    - reporting virtual nodes as missing;
    - `*` handling that lets a bypass pick a wrong concrete type when a concrete match exists (step 3 of the port comes before step 4).
