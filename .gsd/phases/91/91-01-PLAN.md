# Plan 91.1: Shared Validator and Pre-flight Checker

## Objective

Move `ApiPromptValidator` into the app and make it usable against a live server:
- the graph argument becomes optional;
- file names are checked in live mode, with upload skips.

Then add `PreflightChecker`, which turns violations into user-facing `PreflightIssue`s: grouped by node, ordered, in plain wording.

This is pure Kotlin with no UI, fully covered by unit tests. Plans 91.2 and 91.3 build on it.

  <files>

  <action>
    1. In `PreflightIssue.kt` (D-13), define the model Phase 92 will reuse:
       - `enum class PreflightIssueKind { MISSING_NODE_TYPE, MISSING_FILE, INVALID_VALUE, MISSING_INPUT, CONVERSION }`, declared in display order (D-10);
       - `data class PreflightIssue(val nodeId: String, val kind: PreflightIssueKind, val message: String)`;
       - `data class PreflightNodeIssues(val nodeId: String, val title: String?, val classType: String, val issues: List<PreflightIssue>)`, with `val heading` = `"$title ($classType)"`, or `classType` when the title is null or equals the class type;
       - `data class PreflightResult(val nodes: List<PreflightNodeIssues>)`, with `isEmpty`, `count(kind)`, and `summary()`. The summary is e.g. "2 missing node types, 1 missing model file". Pluralise simply, and join the non-zero kinds in enum order.
    2. `object PreflightChecker` with:
       `fun check(promptJson: String, objectInfo: JsonObject, options: ApiPromptValidator.Options): PreflightResult`
       - Parse the prompt. On a parse failure, return an empty result and log `PREFLIGHT_DEBUG`, because the server will report it.
       - Run the validator with `graph = null`.
       - Map each violation per D-09:
         - C1 → MISSING_NODE_TYPE: "Node type X isn't installed on the server".
         - C4 → MISSING_INPUT: "Required input *key* has no value or link".
         - C5 → MISSING_FILE when the value matches the file pattern (reuse the validator's `FILE_VALUE`; make it `internal`): "*value* isn't on the server. Available: a, b, c…". Otherwise → INVALID_VALUE: "*value* isn't a valid option for *key*".
         - C2, C3, C6, C7 → CONVERSION: "The workflow didn't convert cleanly (details in the log)". Keep **one** CONVERSION issue per node, and log every raw violation under `PREFLIGHT_DEBUG`.
       - Group by node. The title comes from `_meta.title` and the class type from `class_type` (RESEARCH §6).
       - Sort nodes by their most severe kind (enum order), then by numeric node id when it parses, else by string. Sort issues within a node by kind.
    Avoid:
    - Android imports: use `println` for the log like the converter, so it runs in JVM tests;
    - truncating the list (D-10).
  </action>
  <verify>gradlew.bat compileDebugKotlin</verify>
  <done>Both files compile with no Android dependencies; `PreflightChecker.check` returns grouped, ordered issues.</done>
