# Plan 94.2: Expand Dynamic Combos in the Converter

## Objective

Convert `COMFY_DYNAMICCOMBO_V3` inputs the way the frontend saves them and the server reads them: send the selected key, then the selected option's sub-inputs as dotted keys, consuming their `widgets_values` in order so later widgets stay aligned (D-02, D-03).

**Depends on**: Plan 94.1 (the validator and baseline that measure this plan)

  <name>Spec-based widget helpers and recursive dynamic expansion</name>
  <files>app/src/main/java/com/example/comfyui_remote/domain/GraphToApiConverter.kt</files>
  <action>
    Refactor the Mode B helpers so they work on a spec (`JsonArray`), not only on a top-level key:
    - `expectedType(spec)` maps a legacy list to COMBO and keeps V3 `COMBO` as COMBO;
    - `findNextCompatibleWidget(spec)`;
    - `resolveComboValue(spec, value)`, which also reads V3 `["COMBO", {"options": [...]}]` option lists.
    Keep the existing top-level behaviour identical.
    Add `expandDynamic(prefix: String, spec: JsonArray)`:
    1. Consume the next widget as the selected key and resolve it against the option `key`s. Emit `inputs[prefix] = key`.
    2. Find the option. If none matches, log `CONVERT_DEBUG` and stop.
    3. For each `(name, subSpec)` in `option.inputs.required`, then `option.inputs.optional`, with `path = "$prefix.$name"`:
       - a nested dynamic combo → recurse;
       - autogrow → copy linked graph slots starting with `"$path."`, as in Phase 86;
       - a graph slot named `path` with a link → emit the resolved link, and if the slot has a `widget` property, consume one widget value;
       - a primitive or COMBO widget type → consume the next compatible widget and emit it (through `resolveComboValue`);
       - otherwise (an unlinked socket) → nothing.
    Honour Phase 93 promoted overrides keyed by the dotted path.
    In the main loop, call `expandDynamic(key, spec)` when the top-level spec type is `COMFY_DYNAMICCOMBO_V3`; top-level linked dynamic keys keep today's link handling.
    Avoid:
    - emitting sub-inputs of options that aren't selected;
    - consuming widgets for socket-only sub-inputs (they have no widget in the frontend);
    - touching the order of later top-level widgets.
  </action>
