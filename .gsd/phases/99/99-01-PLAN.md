# Plan 99.1: Extension v2 Queue

## Objective

Give `comfyui_remote_helper` a managed queue: an explicit order, move, retry, clear finished, and a full-list websocket event. The app can then reorder and retry, and every client sees the same queue (99-CONTEXT D-02, D-03).

## Context

- .gsd/phases/99/99-CONTEXT.md
- server/comfyui_remote_helper/downloader.py, __init__.py, validation.py, README.md

<task type="auto">
  <name>Ordered queue in downloader.py, with tests</name>
  <files>
    server/comfyui_remote_helper/downloader.py
    server/comfyui_remote_helper/test_downloader.py (new)
  </files>
  <action>
    1. Replace `self._queue` (`asyncio.Queue`) with `self._order: list[str]` of queued job ids and `self._wake = asyncio.Event()`. The worker loops as follows:
       - wait for the event while `_order` is empty;
       - otherwise pop `_order[0]` and run `_download`.
       Keep the lazy worker start in `enqueue`, and create the Event lazily inside the running loop.
    2. `cancel(id)`: a queued job is removed from `_order` and marked cancelled. A downloading job keeps the current flag behaviour.
    3. `move(id, position)`: queued jobs only. The 1-based position is clamped to `1..len(_order)`. Returns the job, or None if the job isn't queued.
    4. `retry(id, exists)`: error or cancelled jobs only.
       - Raises `RequestError(409)` if `exists(target)` is true or the same target is pending.
       - Queues a new job with the same url, directory, filename and target at the end, and deletes the old job.
    5. `clear_finished()`: deletes done, error and cancelled jobs.
    6. `jobs()` order:
       - the downloading job;
       - queued jobs in `_order` order, each with `"position": i + 1`;
       - finished jobs, newest first (track `finished_at`).
       Other entries have `position: None`. Keep the public fields and add `position`.
    7. `_emit_queue()` sends `("remote_helper.queue", {"jobs": self.jobs()})` after enqueue, cancel, move, retry, clear, and every status change. The per-job `remote_helper.download` progress events stay, at most once a second.

    `test_downloader.py` (`unittest.IsolatedAsyncioTestCase`):
    - build a `Downloader` with a list-collecting `send`;
    - replace `_download` with an async stub that records the order and waits on a per-test `asyncio.Event`, so jobs can be held in "downloading".

    Cases:
    - FIFO;
    - moving the last queued job to position 1 makes it run next;
    - cancelling a queued job takes it out of `jobs()` positions;
    - retry of an error job re-queues it at the end with a new id;
    - retry when the file exists gives 409;
    - `clear_finished` keeps queued and downloading jobs;
    - positions are 1..n;
    - a `remote_helper.queue` event is emitted after a move.

    AVOID: running downloads in parallel. The user wants one model at a time.
  </action>
  <verify>python -m unittest discover -s server/comfyui_remote_helper -p "test_*.py"</verify>
  <done>All validation and downloader tests pass.</done>
</task>
